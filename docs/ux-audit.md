# UX/UI-аудит CC Deck

Дата: 2026-11-19 · Версия: 0.1.7 + локальный коммит `8e661c3` · Что смотрели: `ui/index.html`, `ui/app.js`, `ui/style.css`, команды в `src-tauri/src/lib.rs`.
Использованы чек-листы скиллов `design:design-critique`, `design:ux-copy` и `design:accessibility-review` (WCAG 2.1 AA, для размеров целей — 2.5.8 из WCAG 2.2).

> **Ограничение.** Приложение вживую не запускалось: `npm run dev` открывает окно на экране пользователя, а снять скриншот нативного окна Tauri из этой сессии нельзя. Всё ниже получено из кода. Контраст рассчитан по формуле WCAG из CSS-токенов (`style.css:1-30`). Перед правками стоит пройти сценарии 1–6 руками и проверить выводы.

---

## Резюме: 5 главных проблем

1. **Модель «аккаунт чата → аккаунт проекта → основной» не видна.** Метка у кнопки «Открыть» показывает только имя аккаунта. Откуда оно взялось, видно лишь по толщине рамки (`.chip.own`) и из всплывающей подсказки. В меню метки нет пункта «как у проекта», поэтому вернуть чат к аккаунту проекта неочевидно. Именно отсюда ощущение «непонятно, как это работает».
2. **Некоторые выборы молча запоминаются навсегда.** «VS Code ▸ → под аккаунтом X» и кнопка «Открыть под …» в диалоге лимита на самом деле **переназначают аккаунт** проекта или чата (`openProject`, `app.js:659`; `preflight`, `app.js:587-590`). Человек думает, что выбрал аккаунт на один раз, а потом удивляется, почему проект «переехал».
3. **Плохо работает клавиатура, и многое видно только при наведении.** Кнопка «VS Code ▸» у проекта появляется только при наведении мыши (`style.css:338`). Проекты в боковой панели — это `div` без фокуса. Меню нельзя пройти клавишами. У модальных окон нет ловушки фокуса и роли `dialog`. Видимого `:focus-visible` нет совсем, а у поиска и полей обводка отключена (`outline: none`).
4. **Не хватает контраста в светлой теме.** Белый текст на акцентном цвете — **3.12:1** (это все `primary`-кнопки и «Открыть» под курсором). Предупреждения цветом `--warn` — **2.9:1** и **2.5:1**. Имя аккаунта у проекта цветом аккаунта — **2.1–3.1:1**. Мелкий серый текст в боковой панели — **4.04:1**. Рамки кнопок — **1.2–1.3:1**, поэтому «призрачные» кнопки почти не отличаются от фона.
5. **Тексты частично технические и не везде одинаковые.** «Папка конфига (CLAUDE_CONFIG_DIR)», «История не общая с основным аккаунтом», «Починить», сырые ошибки из бэкенда в тостах, «Открыл терминал» от первого лица рядом с безличными фразами. Пользователя постоянно просят «нажать ⟳», хотя при возврате фокуса в окно аккаунты и так перечитываются (`app.js:1004`).

## Находки по приоритету

### 🔴 Критично

#### К1. Не видно, почему у чата именно этот аккаунт, и не вернуть «как у проекта»
- **Где:** метка `chip()` у каждого чата (`app.js:566`, `790`). Меню `chatAccountMenu` (`app.js:534-555`). Подсказки `WHY` (`app.js:757-761`).
- **Проблема:** три уровня (чат, проект, основной) отличаются только толщиной рамки (`.chip.own`, `style.css:282`). Подсказка видна только при наведении, а это поздно и ненадёжно. В меню два одинаковых списка аккаунтов под разными заголовками («Этот чат открывать под:» и «Весь проект …:»), и легко нажать не в тот. Сбросить выбор для чата можно только одним способом: выбрать аккаунт, совпадающий с аккаунтом проекта (`setChatAccount`, `app.js:517`). Об этом нигде не сказано.
- **Предложение:**
  - Показать источник прямо в метке маленькой второй строкой или суффиксом: `Личный · для чата`, `Рабочий · как у проекта`, `Рабочий · основной`. Если места мало, хватит иконки: 📌 для чата, 📁 для проекта, без значка для основного.
  - Переделать меню:
    ```
    Открывать этот чат под:
      ● Рабочий            32%  ✓
      ● Личный             81%
      ─────────────
      ↩ Как у проекта (Рабочий)      ← только если у чата свой выбор
    ─────────────
    Изменить аккаунт всего проекта «ccdeck»…
    ```
    Второй список убрать в отдельный пункт, который открывает меню проекта. Так в одном меню не будет двух одинаковых списков.
  - В справке («?») нарисовать цепочку, а не описывать её словами: **Чат → Проект → Основной**, «берётся первый, где выбран аккаунт».

#### К2. Выбор «на один раз» молча запоминается
- **Где:** `openProjectMenu` и `openProject` (`app.js:643-669`): если выбрать другой аккаунт, вызывается `setProjectAccount`. Диалог лимита в `preflight` (`app.js:584-590`): «Открыть под «X»» вызывает `setChatAccount` или `setProjectAccount`.
- **Проблема:** заголовок меню «Открыть «ccdeck» в VS Code под:» читается как разовое действие. На деле все будущие чаты проекта тоже пойдут под новым аккаунтом. После лимита чат так и остаётся на втором аккаунте, хотя лимит первого давно сбросился.
- **Предложение:** честно сказать об этом в интерфейсе.
  - Примечание меню (`app.js:647`): «Проект запомнит этот аккаунт — новые чаты тоже пойдут под ним. История общая.»
  - Тост после выбора (`app.js:668`): «ccdeck открыт в VS Code под «Личный». Теперь это аккаунт проекта.»
  - В диалоге лимита: «Открыть под «Личный»» и строка под кнопками: «Чат запомнит «Личный». Вернуть можно в метке аккаунта у чата.» Можно добавить и третий вариант — подсказку в метке «лимит сброшен — вернуть «Рабочий»?», когда лимит исходного аккаунта восстановится.

#### К3. Важное доступно только мышью и только при наведении
- **Где:** `.proj .proj-open { display:none }` и показ при `:hover` (`style.css:334-339`). `.proj` — это `div` с обработчиком клика (`app.js:691`). Меню `openMenu` (`app.js:813`). Модалки (`app.js:161`). Нет ни одного правила `:focus-visible`, у `.search input` и `.card input` стоит `outline: none` (`style.css:128`, `197`).
- **Проблема:** сценарий 3 («открыть весь проект») с боковой панели не найти, пока не поведёшь мышью именно по строке проекта. Клавиатурой туда не попасть (WCAG 2.1.1). Фокус на кнопках не виден (2.4.7). Меню открывается, но стрелки и Tab по нему не ходят. Из модалки Tab уходит в список под ней (2.4.3). Esc в диалоге `choose()` закрывает окно, но промис так и не завершается (`app.js:945`): `preflight` зависает. Пользователь этого не видит, но так копятся «подвисшие» действия.
- **Предложение:**
  - Сделать проекты кнопками (`<button class="proj">`), а «VS Code ▸» показывать всегда, приглушённо (`opacity:.0 → .55`, при hover/focus — 1), или показывать его хотя бы при `:focus-within`.
  - Добавить глобальное правило `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }` и убрать `outline:none` у полей.
  - Меню: `role="menu"`, `role="menuitem"`, стрелки вверх и вниз, Esc с возвратом фокуса на кнопку, которая открыла меню.
  - Модалки: `role="dialog" aria-modal="true" aria-labelledby`, ловушка Tab и возврат фокуса. По Esc вызывать `resolve(null)`.

| `--warn`: «Вход в тот же аккаунт…», «данные от …», бейдж «лимит 97%» | #c98a1b / #fff и #efede8 | 2.94 / 2.52 | 4.5 | ❌ |

| `--muted` в боковой панели: «АККАУНТЫ», email, строки лимитов (11–12 px) | #76736d / #efede8 | 4.04 | 4.5 | ❌ |

Тёмная тема в основном проходит: muted 5.3–5.9, warn 7.3, ok 6.1, цвета аккаунтов 4.5–6.8. Исключения: белый на акценте **3.12** (акцент в тёмной теме не переопределён), тост ошибки (белый на #e0695b) **3.31**, рамки **1.25–1.38**.

**Предложение:** `--accent-strong: #b85a3c` для фона `primary`-кнопок (с белым ≈4.6:1), `--warn: #9a6608` в светлой теме, `--ok: #2f7547`, `--muted: #6a6761`, `--line` для рамок кнопок ≈ `#bdb8ae`. Имя аккаунта у проекта писать цветом `--text`, а цвет аккаунта показывать точкой, как в метке (`.chip`). В тёмной теме для тоста ошибки — тёмный текст на `--danger` или `--danger: #b5473b`.

#### В2. «Открыть» — главная кнопка, но в покое она не выглядит главной
- **Где:** `.row .actions .go` (`style.css:160`, `244`, `283-284`: три разных правила, последнее перекрывает остальные).
- **Проблема:** пока строка не выделена, «Открыть» — серая кнопка рядом с цветной меткой, и метка выглядит важнее. Акцентный цвет появляется только под курсором. Полоска слева у строки окрашена в цвет аккаунта, а кнопка — в акцент, поэтому связь «откроется под этим аккаунтом» визуально рвётся.
- **Предложение:** оставить одно правило. В покое — заметная обводка акцентом, под курсором — заливка. Либо красить «Открыть» в цвет аккаунта чата, тогда метка и кнопка читаются как одно целое («Открыть ● Личный»). Предварительно проверить контраст белого на палитре: сейчас он 2.4–3.7, палитру придётся затемнить.

#### В3. Сценарий «упёрся в лимит» срабатывает поздно и опирается на устаревшие данные
- **Где:** `LIMIT_WARN = 95` (`app.js:5`), бейдж в строке (`app.js:800`), `preflight` (`app.js:575`), подсказка `usageAge` (`app.js:273`).
- **Проблема:** полоса лимита становится красной с 85%, а предупреждение и предложение сменить аккаунт появляются только с 95%. Лимиты обновляются при запуске, по ⟳ и по «Проверить лимиты», но не перед открытием чата. Чат может открыться под аккаунтом, который уже исчерпан, и человек узнает об этом только в VS Code. Если лимит исчерпан у **обоих** аккаунтов, `preflight` всё равно предложит второй.
- **Предложение:**
  - Перед «Открыть» тихо обновлять лимиты аккаунта, если данным больше 15 минут (бэкенд уже защищён ограничением «Только что проверяли…», `lib.rs:105`).
  - Порог предложения оставить 95, но бейдж в строке показывать с 85: «у «Рабочий» осталось 10%».
  - Если хуже у обоих — отдельный текст: «Лимит почти исчерпан у обоих аккаунтов. «Рабочий» сбросится через 1 ч 20 мин, «Личный» — в пт.»
  - Текст «Всё равно открыть» в диалоге «Чат уже открыт» (`app.js:600`) неясен: под каким аккаунтом откроется? Лучше «Открыть всё равно (останется «Рабочий»)» или вообще кнопка «Понятно, закрою вкладку».

#### В4. Первый запуск: шаги не собраны в один путь
- **Где:** справка показывается сама при первом запуске (`app.js:1013`). Плашка `renderBanner` (`app.js:460-479`). `addAccount` (`app.js:368-405`).
- **Проблема:**
  - Справка про «смените аккаунт у чата» всплывает, даже когда аккаунт всего один и менять не на что.
  - Плашка подсказывает только «установить Claude Code» и «настроить VS Code». Шага «добавить второй аккаунт» нет, хотя без него приложение бесполезно.
  - Слова «Последний шаг» неверны, если второй аккаунт ещё не добавлен или в него не выполнен вход.
  - После «Создать» открывается отчёт со списком технических строк, «Готово» (основная кнопка) и отдельным блоком «Войти сейчас». Две основные кнопки спорят, и проще нажать «Готово» и пропустить вход.
- **Предложение:**
  - Сделать плашку чек-листом из 3–4 пунктов с галочками: «✓ Claude Code установлен · ✓ Второй аккаунт добавлен · ○ Вход в «Личный» · ○ VS Code настроен», где у первого невыполненного пункта есть кнопка. Скрывать плашку, когда всё выполнено.
  - Справку показывать автоматически, только когда аккаунтов уже два.
  - Диалог после создания: заголовок «Аккаунт «Личный» создан», текст «Осталось войти — откроется терминал, войдите **другим** аккаунтом, не тем, что в «Рабочий».», кнопки «Позже» / **«Войти»**. Технический отчёт спрятать под «Подробнее».

#### В5. Пользователя просят «нажать ⟳», хотя приложение может обновиться само
- **Где:** тосты в `app.js:312`, `400`, `427`, `491`. Текст плашки установки (`app.js:466`).
- **Проблема:** при возврате в окно (`focus`, `app.js:1004`) аккаунты и интеграция уже перечитываются. Указание «нажмите ⟳» заставляет искать маленькую иконку справа вверху без подписи. А если её не нажать, ничего не меняется, хотя всё и так обновилось бы.
- **Предложение:** убрать «нажмите ⟳» из текстов. После входа или установки опрашивать `get_accounts` / `claude_status` каждые 3 с, пока статус не сменится, и показать тост «Вход в «Личный» выполнен ✓». Тексты: «Откроется терминал — войдите в аккаунт. CC Deck подхватит вход сам.»

#### В6. Поиск: пустой результат никуда не ведёт, скрытые чаты не видно
- **Где:** `renderList` (`app.js:776`, `808`). `#hide-missing` (`index.html:35`).
- **Проблема:** «Ничего не найдено» — это тупик, хотя рядом есть поиск по тексту переписки (сценарий 5). Счётчик «120 чатов» не говорит, что ещё N чатов скрыто галочкой «Скрыть чаты без папки». Поиск не учитывает имя аккаунта, хотя «чаты под Личным» — естественный запрос.
- **Предложение:**
  - Пустое состояние: «В названиях и путях ничего нет по «oauth». **[Искать в тексте переписки]**». Если что-то скрыто: «Ещё 3 чата скрыты — у них нет папки. [Показать]».
  - Счётчик: «120 чатов · 14 скрыто».
  - В фильтр добавить имя аккаунта (`chatAccount(s).acc.name`).

#### В7. Открытие проекта: у основной кнопки нет признака меню, и она дублирует кнопку из боковой панели
- **Где:** панель проекта (`app.js:727-729`).
- **Проблема:** «Открыть проект в VS Code» выглядит как действие, но открывает меню выбора аккаунта. Рядом ещё три кнопки и метка. «Новый чат в VS Code» и «Новый чат в терминале» по весу равны основному действию.
- **Предложение:** «Открыть проект в VS Code ▾» или сразу открывать под аккаунтом проекта, а выбор аккаунта оставить метке «Аккаунт проекта», которая уже есть рядом. «Новый чат» объединить в одну кнопку-меню «Новый чат ▾ (VS Code / терминал)».

#### В8. Ошибки показываются как есть и исчезают
- **Где:** `call()` и `toast(String(e), true)` (`app.js:77-84`). Тосты исчезают через 7 с без кнопки закрытия, без `aria-live` (`index.html:49`).
- **Проблема:** тексты бэкенда бывают техническими («VS Code: <ошибка ОС>», `lib.rs:463`, «Нет аккаунта {id}», `lib.rs:46`). Длинную ошибку не успеть прочитать, а скопировать нельзя.
- **Предложение:** для ошибок — тост с кнопкой «×» и «Скопировать», без автоскрытия. Добавить `role="status" aria-live="polite"` (для ошибок — `role="alert"`). На фронте обернуть известные ошибки в формат «что случилось + что делать», например «Не нашёл VS Code или Cursor с расширением Claude Code. Установите расширение и нажмите «Настроить VS Code» ещё раз.»

#### В9. Карточка аккаунта перегружена
- **Где:** `renderAccounts` (`app.js:283-301`).
- **Проблема:** в одной карточке до 9 строк: имя, бейдж, ✎, email с ✓, две полосы лимитов, «обновлено …», ссылка «Проверить лимиты», предупреждения и кнопки. Что значит «✓», понятно только из подсказки. Чтобы ответить на вопрос сценария 6 («какой аккаунт где работает»), надо сопоставить счётчик «● 2» в карточке с бейджами в списке.
- **Предложение:**
  - Строка email: «user@mail.ru ✓», где у ✓ видимая подпись при наведении и `aria-label="вход проверен"`.
  - Время обновления и «Проверить лимиты» объединить в одну строку: «обновлено 5 мин назад · ⟳ обновить».
  - Счётчик «● 2 открыто» сделать кликабельным: фильтр списка «открытые под этим аккаунтом».
  - Плюс постоянный фильтр в шапке: «Все · Открытые · по аккаунту».

## Быстрые победы (минуты)

1. Глобальный `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }` и убрать `outline:none` у полей (`style.css:128`, `197`).
2. По Esc в `choose()` вызывать `resolve(null)` (`app.js:945`).
3. `aria-label` для ✎ ⋯ ⟳ 📂 ✕ ?; `role="status" aria-live="polite"` у `#toast`.
4. Затемнить токены светлой темы: `--muted #6a6761`, `--warn #9a6608`, `--ok #2f7547`. Ввести `--accent-strong #b85a3c` для фона `primary`.
5. `.pacc` писать цветом `--text` с цветной точкой.
6. Показывать «VS Code ▸» и при `.proj:focus-within`, а проекты сделать `button` (или `tabindex="0"` и обработчик Enter).
7. Добавить «▾» к «Открыть проект в VS Code» (`app.js:727`).
8. Примечание в меню «Открыть под»: «Проект запомнит этот аккаунт…» (`app.js:647`).
9. Пустое состояние поиска с кнопкой «Искать в тексте переписки».
10. Убрать «нажмите ⟳» из 4 тостов. Обновление по фокусу уже есть.
11. Пункт «↩ Как у проекта (X)» в меню метки чата, если у чата свой выбор.
12. Блок «Клавиши» в справке «?».
