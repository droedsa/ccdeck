# CC Deck

Переключение между аккаунтами Claude Code (например, личным и рабочим) и управление сессиями.
Работает на Windows и macOS, сделано на Tauri 2 (Rust + HTML/JS).

## Как это устроено

- **Основной аккаунт** — обычный `~/.claude`, переменная `CLAUDE_CONFIG_DIR` не задаётся.
- **Второй аккаунт** — своя папка конфига (по умолчанию `~/.claude-work`), в ней хранится только **вход**.
  Папки `projects` (история сессий и память), `file-history`, `todos`, `plans`, `skills`, `agents`,
  `commands`, `plugins`, `output-styles` и файлы `settings.json`, `CLAUDE.md`, `keybindings.json` —
  это ссылки на основной `~/.claude` (на Windows junction, на macOS symlink).
  Из `~/.claude.json` во второй аккаунт копируются доверенные папки и MCP-серверы, но не логин.
- Поэтому любой чат виден под обоими аккаунтами и продолжается с того же места под любым из них.

## Как пользоваться

1. **Чаты общие для всех аккаунтов.** Любой чат можно продолжить под любым аккаунтом с того же места.
2. **Справа у каждого чата — метка аккаунта** (`● Рабочий ▾`), под которым он откроется. Клик по ней —
   сменить аккаунт **для этого чата** или **для всего проекта**. Жирная рамка — аккаунт выбран именно для чата.
3. **«Открыть»** — открывает VS Code с проектом и сразу этот чат во вкладке Claude
   (`vscode://anthropic.claude-code/open?session=<id>`). В меню ⋯ — «Открыть в терминале».
4. **Лимит.** Если у аккаунта чата ≥ 95% лимита, при открытии CC Deck предложит открыть под другим аккаунтом.
   Если чат уже открыт под другим аккаунтом — предупредит: закройте вкладку и откройте снова.

Порядок выбора аккаунта: выбранный для чата → выбранный для проекта (действует и на вложенные папки) → основной.
Основной аккаунт задаётся в настройках аккаунта (✎). Кнопка «?» вверху показывает короткую справку.

Один раз нужно нажать **«Настроить VS Code»** (баннер над списком) — без этого VS Code не знает о выборе аккаунта.

### Как это работает в VS Code

Кнопка «Настроить VS Code» прописывает в пользовательский `settings.json`
`"claudeCode.claudeProcessWrapper": "<…>/ccdeck/bin/ccdeck-wrap(.exe)"` (меняется только этот ключ, комментарии
не трогаются, перед первой правкой создаётся `settings.json.ccdeck-bak`).

Расширение запускает `ccdeck-wrap <claude> <аргументы>` в папке проекта; обёртка берёт id чата из `--resume=<id>`,
смотрит выбор для чата / проекта в `config.json` CC Deck, выставляет `CLAUDE_CONFIG_DIR` и запускает настоящий claude (ввод/вывод и код выхода
передаются как есть; на Windows дочерние процессы завершаются вместе с обёрткой через Job Object, на macOS — `exec`).
Поэтому разные окна одного VS Code работают под разными аккаунтами одновременно, без перезагрузок.

- `ccdeck-wrap` — это копия (Windows) или ссылка (macOS) на сам CC Deck; запускается по имени файла.
- Запуски пишутся в `wrap-log.jsonl` (папка, аккаунт, почему он выбран, имена флагов — без значений и текста запросов).
- Ограничение: проверку входа расширение делает из домашней папки, поэтому в его шапке может отображаться аккаунт
  по умолчанию. Реальный аккаунт чата показывает `/status`.
- Уже открытые вкладки чатов продолжают работать под тем аккаунтом, с которым запустились.
- Cursor и VS Code Insiders подключаются так же (и ссылки открываются в них по своим схемам).

### Клавиши

`/` — поиск, `↑ ↓` или `j k` — выбор чата, `Enter` или двойной клик — открыть, `Shift+Enter` — в терминале,
`Ctrl+Enter` в поиске — искать в переписке, `Esc` — сброс поиска / проекта, `F5` — обновить.

### Трей

Меню иконки в трее: последние 8 чатов (с проектом и аккаунтом) — клик открывает чат в VS Code.

Настройки приложения: `%APPDATA%\ccdeck\config.json` (Windows), `~/Library/Application Support/ccdeck/config.json` (macOS).

## Установка и обновления

Установщики — в [релизах на GitHub](https://github.com/droedsa/ccdeck/releases/latest):
Windows `CC.Deck_*_x64-setup.exe`, macOS `.dmg` (aarch64 — Apple Silicon, x64 — Intel).

Приложение само проверяет обновления (при запуске и раз в 6 часов; вручную — клик по номеру версии
рядом с названием). Обновления подписаны ключом проекта, неподписанное приложение не установит.

## Репозиторий

[github.com/droedsa/ccdeck](https://github.com/droedsa/ccdeck) — код, сборка (GitHub Actions: Windows + macOS)
и релизы, из которых приложение обновляется.

## Выпуск версии

```bash
npm run release            # 0.1.0 → 0.1.1
npm run release -- minor   # → 0.2.0
npm run release -- 1.0.0
```

Скрипт поднимает версию во всех файлах, коммитит, ставит тег `vX.Y.Z` и пушит на GitHub.
GitHub Actions ([`.github/workflows/release.yml`](.github/workflows/release.yml)) по тегу собирает
Windows и macOS, подписывает обновления и публикует релиз с `latest.json` — через ~15 минут
установленные копии предложат обновиться.

**Ключ подписи обновлений** лежит в `~/.tauri/ccdeck.key` (в репозиторий не попадает) и добавлен в секрет
GitHub `TAURI_SIGNING_PRIVATE_KEY`. Сохраните его копию: без него нельзя выпустить обновление, которое
примут уже установленные копии. Публичная часть — в `src-tauri/tauri.conf.json` (`plugins.updater.pubkey`).

## Сборка

Нужны Rust (stable) и Node.js 18+.

```bash
npm install
npm run dev      # запуск в режиме разработки
npm run build    # локальная сборка установщика (нужен TAURI_SIGNING_PRIVATE_KEY=~/.tauri/ccdeck.key)
```

### Windows

Нужны Visual Studio Build Tools (C++) и WebView2 (в Windows 10/11 уже есть).
Установщик: `src-tauri/target/release/bundle/nsis/*.exe`.

Если проект лежит в папке с очень длинным путём, линкер падает с `LNK1104`. Тогда соберите
с коротким target-путём:

```powershell
$env:CARGO_TARGET_DIR = "C:\t\ccdeck"; npm run build
```

### macOS

```bash
xcode-select --install                     # инструменты командной строки, если ещё нет
curl https://sh.rustup.rs -sSf | sh        # Rust, если ещё нет
npm install && npm run build
```

Результат — `src-tauri/target/release/bundle/dmg/*.dmg` и `.app`.
Приложение без подписи Apple, поэтому при первом запуске: правый клик по приложению → «Открыть»,
или `xattr -dr com.apple.quarantine "/Applications/CC Deck.app"`.

**Что проверить на Mac:** на macOS Claude Code хранит токены в Keychain. После добавления второго
аккаунта и входа в него убедитесь, что основной аккаунт не разлогинился (`claude auth status` в
обычном терминале). Если разлогинился, значит текущая версия CLI хранит логины разных
`CLAUDE_CONFIG_DIR` в одной записи Keychain, и для macOS нужно будет доделать подмену записи.

## Отладка

```bash
cd src-tauri
cargo run -- --dump            # аккаунты, сессии и запущенные сессии в JSON
cargo run -- --dump "текст"    # то же + полнотекстовый поиск
cargo test                     # тесты ссылок, settings.json и скрипта запуска
```

(В release-сборке на Windows у приложения нет консоли, поэтому `--dump` там ничего не выведет.)
